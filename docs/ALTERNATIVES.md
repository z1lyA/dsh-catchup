# 备选方案：右栏「会话总览」看板（未采用，留给二期）

这份文档记录的是**没有做**的那一半设计。主线产品（`README.md`）是一个**单会话简报**：你进一个会话之前，打开右栏读一眼它停在哪、有没有事等你。

下面这个方案解决的是另一个问题——**从一堆会话里挑一个切过去**。两者数据同源，代价完全不同，所以记在这里，别丢了。

## 它长什么样

```
右栏面板「会话总览」

⚑ 需要你拍板 · 2
┌────────────────────────────────────┐
│ 登录页限流                   ⚑ 待批准 │
│ 现状：令牌桶已实现，测试挂在 2 个边界用例上 │
│ 待定：等你批准 pwsh 删除临时目录        │
└────────────────────────────────────┘
┌────────────────────────────────────┐
│ 报销台账迁移                  ▶ 运行中 │
│ 现状：31 省并表跑完，正在补台账字段      │
│ 待定：A/B/C 三种字段映射，你倾向哪个？   │
└────────────────────────────────────┘

其余会话 · 6
  数据清洗脚本     ✓ 现状：…   待定：无
  …
```

- 顶部一段只放**需要你动**的会话，按「待批准 > agent 提问 > 未完成 todo > 上一轮报错」排
- 下面是其余会话，按最近活动排，每张卡压缩成一两行
- 点卡片 = 切到那个会话

## 为什么没做

1. **代价不在 token 上，在请求上。** 当前会话的投影是免费到手的（`session/control` 基线带全量 `turnOutline`）；但**冷会话**（没在运行的老会话）的 `turnOutline` / `todos` / `sessionStats` 被官方排除在 `session/list` 的摘要块之外，每个会话要单独发一次 `session/projections`，host 端会读一遍那个会话的完整日志。30 个会话 = 30 次请求 + 30 次日志重放。
2. **它回答的不是用户当时提的那个问题。** 原始需求是"减少切换会话时消耗的认知成本"——这句话在实测里被拆成了两件事：挑谁会话（看板）和读完一个会话的现状（简报）。后者才是高频动作，前者一周几次。
3. **右栏布局是每个会话一套的**（`dsh.sidebar-right.v1.<sessionId>`），所以一个"全局看板"挂在右栏里天生别扭：你从 A 点去 C，C 有自己的布局，看板可能是关着的。

## 如果要做，怎么做才不亏

- **两级**：先用 `session/list` 白送的那点东西渲染卡片（`title`、`userQuestions`（含问题原文和选项）、`goal`、`plan`、`sessionListMetadata.lastPromptAt`、`tokenUsage`、`workingDirectory`）——这一层对**所有**会话都是 0 请求、0 token。
- 冷会话的「现状句」**只在卡片进入视口 / 展开时**才发那一次 `session/projections`，别预取全部。
- 「⚑ 需要你拍板」那一段完全不依赖冷会话取数，所以它永远秒出——先把这一段做出来就有八成价值。

## 可复用的代码

单会话简报里的三个纯函数可以原样搬过来：

- `lastState(turnOutline)` — 从最后一轮取现状句
- `pendingOf(session)` — 按优先级算出"待你拍板"的那一条
- `catchupLine(...)` — 压成一行

## 3. 面板里内嵌一个「追问」对话（已评估，暂不做）

场景：读到一句不懂的，不想在主会话里问（怕污染上下文），想岔开问一句。

两条路，都验证过（DSH 0.2.2-rc.5）：

| | 做法 | 上下文 | 成本 | 代价 |
|---|---|---|---|---|
| B1 | `sessions.fork()` 分叉当前会话 + `sessions.retain()` + `renderFactorySlot('conversation.content', { variant: 'embedded' })` | 完整继承 | 正常对话成本 | 侧栏多一个会话；回答不进主会话 |
| B2 | Host 调 `ctx.llm` 自己画气泡 | 只有喂进去的几段 | 一次一问 ≈ 一次摘要 | 没有工具、没有历史、回答不落盘 |

客户端**不能**自己调模型（`ctx.llm` 只在 Host），也**不能**生成子代理。

暂不做的原因：引用（`inputActions.insertQuote`）已经覆盖"不懂一句、问一下"的主路径，而 B1/B2 都会引入"两个对话"的概念。真要做，选 B1——同一个功能，B1 是十行配置，B2 是两百行还要维护。

## 4. 本会话花费（已评估，不做）

`累计` 是全局账本（`totals.json`，不分会话）。用户确认不需要会话级的数字：同一行里放两个成本会互相打架。

## 数据来源备查（2026-11 于 DSH 0.2.2-rc.5 验证）

| 数据 | 在哪 | 冷会话要额外请求吗 |
|---|---|---|
| `turnOutline`（每轮 prompt ≤50 字 + response ≤120 字） | `projectionsBySession[id].values.turnOutline` | **要**，1 次/会话 |
| `todos` | 同上 | **要**，1 次/会话 |
| `sessionStats` | 同上 | **要**，1 次/会话 |
| `userQuestions`（问题原文 + 选项） | `session/list` 摘要块 | 不要 |
| `title` / `goal` / `plan` / `lastPromptAt` / `tokenUsage` / `workingDirectory` | `session/list` 摘要块 | 不要 |
| 运行中 / 待批准 / 未读 | `useSessionStatus()`（实时推送） | 不要 |
| `approvalState` | **浏览器读不到**（host-only，无 wire） | 永远读不到 |
